# 病理图像训练/验证清单划分与素材打包系统

Flask + SQLite 单容器应用：上传全量图像 CSV 与重复图像关系 CSV，按各类别验证张数配额，
把图像划分为**训练侧**与**验证侧**两份可下载清单；再把清单图像原件（素材 ZIP）打包成
`train/`、`val/` 两个目录的素材包，供训练程序直接读取。

## 核心业务规则

1. **连通分量是最小分配单元**：同一患者的所有图像、以及重复图像关系 CSV 中连通的图像
   （并查集合并，含传递链）必须整体在同一侧。
2. **精确满足配额**：验证侧每个类别的图像张数必须与填写的配额**精确相等**；
   多维 0/1 背包 DP 在 ≤40 张、≤4 类的状态空间内求精确解。
3. **侧别永久固定**：成功发布即把每张图像的侧别写入全局唯一的 `side_registry` 登记表。
   之后即使删除数据重新上传同一图像，其侧别也不会改变；新划分必须服从登记。
4. **无解不发布**：
   - *关联冲突 (conflict)*：一个连通分量内的已发布图像被固定在不同侧；
   - *配额不可达 (quota)*：锁定图像已超配额，或自由分量不存在精确凑出配额的组合。
   页面给出人类可读原因 + 结构化诊断（最接近的可达组合、自由分量向量等），不产生清单。
5. **更正即新版本**：重新上传 CSV 或修改配额都会生成新输入版本，旧版本立即变为
   `superseded`，旧清单仅作历史保留、**下载停供**；新版本重新划分成功后下载才恢复。
6. **求解期间可更正，过期依据不发布**：作业发布前复查版本新鲜度，版本已过期则判 `stale`
   失败，不写任何分配。
7. **并发与原子性**：
   - 部分唯一索引保证同一版本至多一个进行中/成功作业、至多一份已发布清单；
   - 清单、明细、侧别登记在单个 `BEGIN IMMEDIATE` 事务内提交，失败整体回滚，
     不会留下半次分配；
   - 服务重启时残留的 `queued/running` 作业一律标记 `restart` 失败（它们从未写入分配）。
8. **规模限制**：最多 40 张图像、4 个类别。

## 素材打包（第二阶段）

在清单发布后，数据员上传素材 ZIP 生成训练可直接读取的素材包：

```
素材 ZIP 根目录/
  files.csv          图像号,ZIP 内路径,SHA-256（也支持英文表头或无表头按列序）
  images/...         原件
```

校验规则（任一不通过即整包失败、不生成任何文件，页面逐条列出原因）：

| 类别 | 规则 |
| --- | --- |
| 格式 format | 必须是可读 ZIP；根目录有且只有一个 `files.csv`；表头可识别；三列非空 |
| 路径 path | 必须位于 `images/` 下；禁止绝对路径、盘符、`..`、反斜杠、控制字符、符号链接、加密条目 |
| 映射 mapping | 清单图像必须一一对应：每张图恰好一条映射，图像号不得重复，同一 ZIP 内路径不得被多张图共用，不得出现清单外的多余映射 |
| 缺件 missing | 清单每张图像都必须有映射，且映射的 ZIP 内文件真实存在且不是目录 |
| 单件 size | 每个原件解压后 ≤ 5 MiB（ZIP 头声明与实际流式读取双重校验，超限即中止） |
| 摘要 digest | 逐件流式重算 SHA-256，必须与 files.csv 声明一致；读取失败同样报原因 |

通过后按清单侧别生成：

```
素材包.zip
  manifest.csv    图像号,患者号,类别,侧别,文件路径,SHA-256（UTF-8）
  train/images/…  训练侧原件（保留原 images/ 相对路径）
  val/images/…    验证侧原件
```

一致性保证：

- **制包期间输入被更正**：发布前复查清单仍是当前已发布清单、所属版本仍为 `active`，
  否则作业判 `stale` 失败，包文件删除，不登记下载；
- **发布后更正输入**：新版本事务提交后，旧包登记立即 `superseded` 并删除文件，下载停供；
- **并发**：同清单并发上传只登记一个 `queued/running` 作业（部分唯一索引），
  已发布包每清单至多一份；内容完全相同的重复上传直接复用已有包；
- **中断安全**：上传先落临时目录，输出包先写临时文件、`fsync` 后再 `os.replace` 到正式目录；
  数据库登记是最后的原子步骤，失败则回滚并删除文件。服务重启把残留 `queued/running`
  制包作业判 `restart` 失败，并清理临时目录与未登记的半包——任何时刻都不会出现可下载的半包。

## 目录结构

```
app/
  db.py        SQLite 建表、索引、连接与重启恢复
  parser.py    CSV 解析（中英表头/无表头/BOM/GBK）、输入校验、并查集
  solver.py    锁定校验 + 多维 DP 精确配额 + 无解诊断
  packaging.py 素材 ZIP 校验（映射/路径/缺件/5 MiB/摘要）与 train/val 制包
  service.py   输入版本、作业调度、原子发布、素材包发布/停供、历史与下载
  web.py       Flask 路由
  templates/   中文网页（当前版本/作业原因/素材包/历史/永久登记）
wsgi.py        waitress 生产入口
tests/         55 项 pytest（求解器、端到端流程、素材制包与网页流程）
samples/       示例 CSV
Dockerfile, docker-compose.yml
```

## 启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8080
```

SQLite 数据保存在命名卷 `pathology_data`（容器内 `/data/pathology.db`），重启不丢。
健康检查由 Compose / Dockerfile 内置。

## 本地运行（无 Docker 时）

```bash
pip install -r requirements.txt
DB_PATH=./data/pathology.db python wsgi.py
# 自测：
PYX_SYNCHRONOUS=1 python -m pytest tests/ -q
```

## CSV 格式

全量图像 CSV（首行表头可省略，列顺序固定）：

```
图像号,患者号,类别
IMG001,P001,肿瘤
IMG002,P001,肿瘤
```

重复图像关系 CSV（可不上传）：

```
图像号A,图像号B
IMG003,IMG006
```

## 页面操作

- **当前版本 `/`**：上传/更正 CSV、填写各类验证张数、发起划分、查看当前清单与下载两侧 CSV；
- **作业页 `/jobs/<id>`**：求解状态自动轮询；失败时展示关联冲突/配额不可达原因与诊断；
- **历史 `/history`**：所有输入版本、作业（含失败原因）、已发布清单；历史版本下载停供；
- **永久侧别登记 `/registry`**：全局图像侧别锁定表。

下载文件为 UTF-8 CSV：`图像号,患者号,类别,侧别,连通分量`。

- **素材包 `/` 第⑤区**：上传素材 ZIP；成功后在页面直接下载当前包，失败则跳转制包作业页
  逐条展示原因（缺件/重复映射/摘要不符/越界路径/单件超限/格式错误）；
- **制包作业 `/packages/<id>`**：作业状态自动轮询、失败原因与问题清单、包摘要与下载；
- **历史 `/history`**：额外列出全部素材包（当前/已停供）与制包作业。

## 素材包存放

| 路径 | 说明 |
| --- | --- |
| `PACKAGE_DIR`（默认数据库同目录 `packages/`） | 已发布素材包；只保留数据库登记为 published 的文件 |
| `PACKAGE_DIR/_tmp` | 上传临时文件与制包临时文件；作业结束/重启清理 |

## 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DB_PATH` | `/data/pathology.db` | SQLite 数据库路径 |
| `PACKAGE_DIR` | 数据库同目录 `packages/` | 素材包与临时文件目录 |
| `PORT` | `8080` | 监听端口 |
| `SECRET_KEY` | 开发占位 | Flask 会话密钥，生产请覆盖 |
| `PYX_SYNCHRONOUS` | `0` | `1` 时划分/制包作业同步执行（测试用） |
| `PYX_SOLVE_DELAY` | `0` | 人工求解延迟秒数（演示过期场景用） |
| `PYX_PACKAGE_DELAY` | `0` | 人工制包延迟秒数（演示制包期间更正场景用） |

素材 ZIP 上传上限 320 MiB（`MAX_SOURCE_BYTES`），单件原件上限 5 MiB 在制包时逐件校验。
